# 原生窗口尝试的证据范围

本机X11可连接并创建真实Vulkan游戏窗口，libX11/XTest仅操作本次启动的游戏与自建焦点窗口，FFmpeg只抓游戏窗口。初次日志参数错误留下的游戏进程已按记录PID和完整命令核对后关闭；随后用_NET_WM_PID避免窗口ID复用误判，用加载日志避免过早切焦吞掉进入请求

修前旧构建实际能显示场景，回焦时没有自动暂停；严格修前FAIL依据仍为CPU测试，旧原生构建未在启动时记录独立binary hash。修后的 `native-fixed/run.json` 仅记AUTOMATION_COMPLETE及退出0，没有将其当作视觉PASS。实际看图发现05仍为暂停，09／10／11图像哈希相同，未据文件名将其解释为成功行走或返回标题

进一步查询niri：无活动窗口，X11内部焦点不证明合成器激活；按本任务窗口尝试focus-window仍未获得is_focused。该次窗口操作停止，遗留的本任务进程已核对命令后关闭，未解锁会话或操作其他应用

本目录保留问题观察、输入时间线和最后的探针源码，不是可用的桌面验收工具。当前源文件是最后一次使用niri的诊断版本；更早尝试有日志参数、窗口定位和等待改动，不宣称该源码逐字复现所有早期脚本。原始PNG、20秒视频和完整日志在output目录；原生失焦／回焦完整验收记INCOMPLETE，物理设备及Windows记NOT RUN

最终渲染验收使用walk-focus.json，同一正式系统接受模拟WindowFocused输入，范围在主review单独说明。它不证明本机桌面合成器行为
