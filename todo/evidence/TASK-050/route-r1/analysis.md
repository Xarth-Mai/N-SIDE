## 当前 capture 的最小使用建议

优先保留 `walk-preview` 正式入口、真实出生点、`move_axis`／普通键鼠输入与真实状态断言，用现有手动事件描述上述路线；原脚本的 400 帧后返回标题会清空记录，应将这段重开验证移到完整确认之后

现有 `RouteDriver` 只按源地图已命名 route 连续行走，而且 Script 契约要求所有手动 events 在 `route.start` 前结束，没有中途观察、停止等待输入或完成后选择的接口，因此不能只换一个 route ID 就完成三点交接；若手动输入不够稳定，再对现有驱动增加有边界的停点输入能力，不需要创建能写入观察目标或任务结果的新 fixture

手动脚本可在移动期间保持 yaw=0，让 `move_axis` 的方向直接等于地图平面 `(dx,dy)` 的单位方向；长度 d 的一段取 `n=ceil(d*fps/3.2)` 帧、原始摇杆模长 `0.15+0.85*d*fps/(3.2*n)`，经生产死区得到对应理论速度。它只是无碰撞损失时的初始时长，台阶摩擦和接缝会影响实际到达，必须读取记录的真实脚点校准，不得把理论积分值作为已到达证据

04 开窗前使用普通鼠标输入将 yaw 转到西向 π/2，默认灵敏度下可用一次 `look:[-523.5988,0]`；关闭并完全释放后以相反输入回到 yaw=0。每次转向、停止、开窗及关闭后预留至少两个空白帧，避免观察目标仍使用上一帧镜头以及生产输入等待释放门槛吞掉后续操作

在 29 与 28 的精确锚点附近，真实相机仍看向脚点上方 1.35m，通常不需额外重置朝向，但必须断言实际 `observation_target`；各次 `F`／手柄 Confirm 后检查 `selected`、`open`、`visible`、三项记录的确切集合与 `confirmation_count=0`

在 28 首次开窗后释放输入，按 Down 切换到台阶，再 F 应得到 `rejected_choices=1` 与 `stage=awaiting_choice`；释放后按 Up 切回侧院，再 F 应得到一次确认；随后关闭、重开及重复 F，确认次数应保持 1。每段还需真实脚点位置、高度、着地、零 resets 与连续画面，CPU 输入／状态 fixture 不能代替这条路径
