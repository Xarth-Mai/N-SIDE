## 运行时与数据边界

保持 `game/` 单 crate，增加 library 和独立 `map_viewer` binary；现有游戏入口保持原有默认启动行为

```text
game/src/
├── main.rs
├── lib.rs
├── bin/map_viewer.rs
└── world/
    ├── mod.rs
    ├── map.rs
    ├── geometry.rs
    └── scene.rs

source-assets/
├── district-map/
├── district-scene/
└── environment-kit/

game/assets/environment/
```

结构已实施，资产诊断独立为 `world/assets.rs`，共享白天配置由 `world/visual.rs` 提供，保持单 crate 与相机独立入口

`map.rs` 负责有类型的地图解析、引用校验和坐标转换；`geometry.rs` 负责地形、道路、平台与建筑几何；`scene.rs` 负责素材绑定、场景生成及源对象关联；`visual.rs` 负责固定曝光、白天天空、环境光、太阳与可选效果组合。Viewer 入口负责窗口、启动加载、飞行相机及验证镜头，共享世界模块不依赖 Viewer 的输入

启动流程为 `JSON → 解析与校验 → Rust 地图数据 → 几何与 Bevy 场景`，运行中使用解析后的数据和实体。地图保持唯一编辑源，模型与贴图作为独立运行资产加载；JSON 不承载 Bevy 组件或 Viewer 配置

统一坐标转换为地图 `[x,y,h]` 到 Bevy `[x,h,-y]`，提供逆转换，1 Bevy unit = 1 meter。二维几何使用 `f64`，生成渲染顶点时转为 `f32`；GLB 导入遵循资产轴向规范，与地图转换分开

`district-scene` 保存可复用的材质、构件与装饰规则，通过源对象 ID 关联空间。来源已有的数据优先，推导几何与表现补充可追溯，场景配置不复制建筑位置和大小。新增描述字段可兼容，未知核心空间语义和不支持的 schema 明确报错

JSON 解析采用 `serde`，多边形裁切和三角化采用成熟库，版本在工程阶段按锁定 Bevy 与真实几何输入验证。性能先测量，出现实际启动成本后再考虑预生成场景或缓存

## 几何与资产接入

建筑生成完整外壳和开放天井，入口与楼层分段读取源值。道路优先采用显式宽度，缺省值集中维护并标为推定；桥、屋顶、电梯和内部通路按层级处理，不参与自然地面插值

自然地形由地面控制点推导，显式道路、平台、基座与水域进行边界裁切和接缝处理。挡墙、桥厚、必要支撑、门窗和装饰可以规则推导；源高程或轮廓存在冲突时保留源值并报告，地图设计修改由空间任务维护

只生成已落位体量，容量留在空间规划中。源输入和外观配置相同，生成结果保持确定；同楼多个地点共用建筑，植物优先使用已有树点

首批采用免费 CC0 模型与材质，字体使用允许分发的开放许可，招牌和简单缺口构件采用项目原创。每个入选文件保存实际来源、作者、许可文本、原文件哈希、唯一主文件与导出方法，完成引擎检查后再标记接入

运行资产采用米制 GLB 和标准 PBR，核对尺寸、枢轴、朝向、法线、UV、材质及透明边缘。工具脚本使用 Bun，仅在资产实际需要转换时使用 Blender；运行 Viewer 不依赖 Blender 或网络

### 加载诊断与失败行为

地图解析和材质加载异常必须可定位，不允许静默 fallback。诊断输出到终端，按读取、解析、校验、几何生成和资产依赖加载区分阶段，不依赖调试界面

| 失败类型 | 必须记录的上下文 | 行为 |
| --- | --- | --- |
| 地图文件读取或 JSON 语法错误 | 输入路径、底层错误，语法错误包含行列 | 启动失败并返回非零退出码 |
| 地图字段类型、引用或核心几何错误 | 输入路径、JSON Pointer 或等价字段路径、可用的对象 ID、实际值和失败原因 | 停止场景生成并返回非零退出码；对象 ID 尚未解析时以字段路径定位 |
| 必需模型、材质或贴图加载失败 | 资产 ID、解析后的文件路径、引用该资产的源对象、模型场景/材质槽，以及失败的依赖链和底层错误 | 等待异步依赖结果，失败时汇总诊断并以非零退出码结束，不能以默认材质报告成功 |
| 显式声明为可选的装饰缺失 | 相同的来源上下文、采用的回退或省略方式 | 输出 Warning，启动摘要明确显示降级项和数量 |

资产默认必需，可选性由资产绑定显式声明。加载句柄已返回不代表成功，材质引用的颜色、法线及其他贴图依赖和场景实例化均纳入启动完成判定；损坏贴图、未知材质引用、不可用材质扩展等可检测错误遵循相同规则

日志合并重复依赖错误并保留受影响对象列表，启动摘要列出成功、失败和降级数量。源空间设计问题保留源值并按对象报告，与解析失败和程序构建失败分别归类；格式合法但风格、反光或颜色不合适的素材由视觉验收判断

### 自动与视觉检查

自动检查覆盖坐标正向与往返、米制尺度、多边形绕序与凹轮廓、天井、道路宽度、竖直电梯、平台上下层、输入引用和资产依赖。使用实际源快照及小型边界样例，现有地图检查继续保留

诊断窄测分别注入无效 JSON、错误字段类型、缺失节点引用、缺失 GLB、错误材质绑定及损坏/缺失贴图，断言错误上下文和失败退出码；另验证显式可选装饰的降级警告及启动摘要，覆盖异步子依赖失败而顶层句柄已创建的情况

工程阶段运行格式检查、Clippy、测试与构建。文档阶段运行 `bun run check:docs`、`bun run check:map`、`bun run docs:build` 与相关 diff 的空白检查
