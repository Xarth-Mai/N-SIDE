### 已明确的 Agent 设定与实现边界

云端 Agent 是游戏世界内的角色设定，不是由现实世界真实 Agent 驱动的系统，也不构成接入在线大模型或云端服务的需求

家庭 Agent 的记忆、语言、工具调用、多机体与潜梦协作通过游戏内内容和行为逻辑呈现，Demo 的支援围绕探索、提示、操作与保护展开，能够离线独立完成

### Demo 的终点

玩家在小店参与日常，接到一份求助，在现实和梦境之间调查，通过观察与行动改变异常的维持条件，看见当事人和地点的后续变化，最后回到仍然营业的小店与楼上住家

城市漫游、孤立战斗房间与纯对白剧情分别作为阶段产物，完整 Demo 以这条内容循环闭合为完成标准

### 建议起始范围

下表为 M0 的建议起点，记录方案不等于批准其中所有范围与设计选项

| 项目 | 建议范围 |
| --- | --- |
| 时长 | 首次正常游玩约 25—40 分钟，由试玩校准，时长来自有效体验 |
| 城市 | 保留完整城市框架，区分可见、可通行、可进入、可交互范围 |
| 主要路线 | 优先“小店—采购街—坡地住宅”，随首个委托调整 |
| 室内 | 小店与住家，加委托需要的一处现实室内 |
| 人物 | 一名可操作兄妹、另一名接应、家庭 Agent、2—3 名委托相关 NPC |
| 内容 | 一份完整异常委托、少量顺路生活互动、完成后的重访变化 |
| 梦境与动作 | 一个梦境主题、一组基础工具动作、一种核心敌人行为模板、一种有效 Agent 支援 |
| 时间 | 初秋白天与夜间两个离散状态 |
| 交付 | Linux、Windows，键鼠与手柄，离线独立完成 |

缩小交互内容与精修范围，保留城市基础；所有允许玩家到达的位置均承担碰撞、边界与基本体验责任

| 空间范围 | 明确可走、可进、外观建筑及转场边界；形成范围图、室内清单、关键路线与视线 |
| UI／UX | 明确接任务、查线索、用工具、常驻信息与手机式界面候选；形成信息架构、页面流程、灰度线框与双输入原则 |
| 美术与声音 | 确定角色与城市协调方式、日常与梦境差异及渲染实验；形成比例草案、视觉板、声音情绪与事件清单 |
| 工程与交付 | 明确参考设备、保存原则、离线边界、依赖验证和包形态；形成技术决策表、验证矩阵、资产与存档约束 |

已定设定沿用：小店全天营业、兄妹一次一人入梦、Agent 以探索与保护为主、云端 Agent 属于游戏内设定。镜头距离、锁定与具体 UI 形态进入原型实验

### M2：日常与调查原型——让行为产生结果

| 领域 | 决策与设计 |
| --- | --- |
| 日常 | 制作一段店务、一次邻里交流、一处停留活动，与首委托共用人物和空间 |
| 调查 | 明确观察、询问、核对、推测与必要线索，设计信息图、交互点、补充路径、不同顺序与防死锁规则 |
| 叙事与状态 | 划分任务阶段、玩家认知、世界事实、NPC 状态和一次性事件的维护责任，设计条件、事件与运行时语义 |
| 时间与 NPC | 明确昼夜切换、等待与人物出现方式，设计离散时段、关键 NPC 活动状态、重访对白 |
| UI／UX | 分别呈现对话、选项、观察、线索、委托摘要、调查记录、关键物品／工具和保存反馈 |
| 人物与声音 | 制作注视、转向、对白结束恢复行动等低成本演出，以及环境音、交互反馈和字幕布局 |
| 存档 | 确定保存内容、时机与恢复位置，设计版本、稳定 ID、检查点、一次性事件和重访／跳过测试 |

从首委托抽出可复用的日常与现实调查，接续既有 `narrative.json` 信息状态与节点资产，实现拿取或交付、交谈、物件检查、线索变化、任务推进、时段切换与存读档

调查界面呈现玩家已观察的事实和当前推测，策划真相按信息获得条件揭示。静态结构检查与引擎变量、条件、存档验证分别记录

验收：陌生试玩者知道当前目标，感知一次行动造成的变化；改变线索顺序、跳过对白、中途退出、重复到访或读档均无信息丢失、重复发放与任务卡死

复杂进销存、全城日程、大型背包和全面好感体系留到 Demo 之后

### M3：潜梦与动作原型——验证理解规则后的行动

| 领域 | 决策与设计 |
| --- | --- |
| 现实与梦境 | 建立物件与地点对应、规则扭曲、回现实核对的时机、转场返回点与连接状态 |
| 动作核心 | 验证攻击、回避、工具，决定自由瞄准／软辅助／锁定及体力需求；设计输入、取消、判定、受击、恢复和镜头 |
| 敌人与高潮 | 制作一种核心敌人行为模板、意图预警、对策、遭遇节奏与机制型高潮，让战斗创造操作核心的机会 |
| 家庭协作 | 明确接应者介入与 Agent 探索、提示、操作、保护的事件、触发、反馈和恢复，保留玩家判断与解题 |
| 失败与退出 | 区分普通失败、主动退出、剧情受困，设计检查点、消耗、结果提交时机与场景任务恢复 |
| UI／UX | 制作潜梦准备、行动 HUD、必要资源、工具与支援状态、危险提示、失败与返回界面 |
| 动画与声音 | 验证攻击可读性、预警、命中反馈，制作功能动画、临时特效声音、镜头与震动设置 |

交付可重复流程：进入 → 观察 → 判断 → 交战或回避 → 使用工具改变局面 → 退出

从一种基础攻击、一种回避、一种关键工具起步，Agent 至少提供一种可感知的有效支援，通过游戏内逻辑实现。处理目标围绕接近核心、解除联系、改变异常维持条件设计，沿用检查点重试

验收：玩家能看懂危险、解释失败原因并按规则使用工具；进入、退出、失败重试、重新入梦后任务、场景与角色状态一致；两种输入均可完成

原型体验不成立时先调整规则与反馈，再决定是否扩展武器、敌人与特效

M4 结束后扩大内容制作。成本过高时先减少地点、角色、分支与覆盖范围，保住样板品质
