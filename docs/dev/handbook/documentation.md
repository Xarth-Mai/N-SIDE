# 文档与知识归属

## 输入与职责

整理文档前读取相关对象、实现、当前任务及原始来源，辨认每段回答的是玩家事实、设计规则、工程契约、制作方法还是本次结果。迁移保留完整信息与语义，不能把长文压成摘要后当作职责分离

| 位置 | 权威内容 |
| --- | --- |
| `docs/player/encyclopedia/` | 世界、人物关系、场所、完整故事、敌人与世界内机制；故事入口和必要章节标记剧透 |
| `docs/player/guide/` | 实际可玩版本的操作与帮助；尚未验证的按键、功能与数值留在开发规格 |
| `docs/dev/direction/` | 愿景、体验支柱、完整游戏与 Demo 范围 |
| `docs/dev/design/` | 玩家动作、信息因果、状态、具体对象与系统规格 |
| `docs/dev/engineering/` | 数据、资产加载、系统生命周期、保存恢复和错误契约 |
| `docs/dev/production/` | 从输入到制作、接入和检查的方法 |
| `docs/dev/validation/` | 验收标准、机器与视觉证据的范围 |
| `docs/dev/handbook/` | 协作、任务、文档、发布与模板规则 |
| `docs/dev/decisions/` | 当前有效且会影响后续工作的取舍与依据 |
| `.agents/skills/` | Codex 执行专业工作的通用方法、工具与项目适配入口 |
| `todo/tasks/`、`todo/evidence/` | 当前工作、依赖、实际结果、阻碍、输入版本与证据 |
| `source-assets/`、`game/assets/` | 唯一资产源与按现有导出流程生成的运行资产 |

同一事实只有一个正文维护位置。开发规格链接百科后补充动作、信息、数据和验收要求；同一人物或地点不因两个阅读视角复制两套设定。作者专用内容保存在开发主题，公开内容按发布规则投影

## 身份与状态

对象继续使用 CHR、LOC、QST、ENM、AST 等原 ID，改名与搬家不换身份。文档需要独立身份时使用 `document_id: DOC-*`，对象正文使用 `subject_id: CHR-001` 等；规格引用同一 subject_id 不会创建第二个对象。机器索引中的对象 `id` 保持原格式

开发设计的 `status` 为 `draft`、`accepted` 或 `superseded`。既有 `approved` 迁移为 `accepted`，在迁移映射中记录；这只是状态名称归一，不产生新的作者批准。任务状态按[任务卡](tasks.md)维护，设计获认可不等于实现完成

标题从一级标题读取，不再保存容易漂移的 title。读者由目录决定，不另存 audience。只保存实际需要的元数据，玩家页面不渲染内部元数据表

## 编辑与拆分

1. 确认原页、对象 ID、结构化数据与消费者；为迁移记录逐文件路径、原始 hash、分段去向和允许的数据变化
2. 按一个主要阅读任务组织页面，混合文档按段落职责拆分，保留上下文、限定、例外和因果链
3. 长期规则归 docs，本轮日志、机器结果和实际反馈归任务证据；已经支持的结论写回相应规格，待验证参数保持未知
4. 同时修正文档链接、锚点、索引路径、Skills、脚本、构建与测试；JSON/CSV 尽量逐字节移动，必要路径变化逐项记录，其余做语义比对
5. 运行文档与受影响消费者检查；涉及发布内容时检查双站实际产物、搜索、数据与静态文件，不以隐藏导航替代发布边界

## 格式与来源

使用中文正文、准确的代码与标识符、UTF-8 和 LF；普通文件名使用 ASCII kebab-case，分类入口用 index.md。每个逻辑段落或列表项占一行，省略自然语言句末标点，保留代码、引用和语法所需标点

链接使用相对 Markdown 路径；模板占位符放行内代码或代码块。Wiki 位图使用质量 80 的 WebP，源工程留在 source-assets，输出图与中间证据分别归其用途目录。现有第三方正文保留原作者格式，不为本地风格改写许可内容

原版 Skill、补丁和改编分别登记固定 commit 与来源文件。复制文本或代码保留完整许可、适用 NOTICE 和方法论归属；Apache 修改文件显著标注修改。Skill 许可不能代替字体、模型、音效或参考图片的许可

## 输出、检查与失败处理

交付正文、迁移映射、已更新消费者和实际检查记录。重复事实合并回权威页，过时入口改为受众允许的跳转；未分类原文件保持可追溯，不静默删除。缺失对象、断链、数据语义变化或玩家包混入开发内容时修复后复验；无法核实的设计状态保留原状态并记录原因
