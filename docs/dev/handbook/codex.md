# Codex 项目工作流

## 输入与定位

从当前仓库、根 AGENTS.md、任务卡、关联规格和最近证据恢复工作，不依赖旧会话印象。先检查分支、提交和未提交内容；用户指定主题优先，已有决定沿用。仅查询状态时保持只读

当前任务的目标、依赖与状态由[任务卡](tasks.md)维护。开始时简述正在做什么、哪一步、下一动作与是否需要作者判断；不恢复旧 61 项分母，也不把迁移、安装 Skill 或生成文档计作游戏能力

## 选择入口与执行

进度查询用 n-side-guide，授权执行用 n-side-work-loop，验收用 n-side-review。专业工作先读 nside 适配入口，再按问题选原版 Skill；叙事沿用 create-case、create-content、review-narrative，避免重复写多份报告

理解目标 → 确定交付与验收 → 制作 → 适用检查 → 必要的真实运行或评审 → 记录与回写。简单小修可压缩，不为每步制造空文档；原型比较少量假设，制作按已确认清单分批，修复保留复现与回归

已授权的技术取舍自主推进。需要改变既定设计、范围、成本、付费授权或破坏性操作时才提出具体取舍；主观体验、陌生玩家理解与阶段放行依据真实反馈。一次反馈可关联多个任务，不重复向作者索取相同决定

## 输出与检查

交付实际文件或可运行入口，列出真实命令、结果、限制和下一动作。代码/场景/UI/视觉/动画依[运行验证](../validation/runtime.md)取得相应深度的证据；纯文档依[文档规范](documentation.md)检查，无需游戏录像

请求作者试玩时提供启动方式、短路线与具体观察问题。需要真实反馈的项保持 review；技术项依据实际检查可以 done。缺环境记录 NOT RUN，失败保留输入与日志并在授权范围内修复。长期结论写回 docs，本轮轨迹与输入版本进入任务 evidence

## 宿主能力检查

Skills 的包装完整性、固定上游来源、宿主发现、模型显式/隐式行为是不同检查。实际模型试验保留输入、版本、工具轨迹和结果，普通百科编辑反例应避免启动制作或写进度；发现列表不能代替行为验证

项目技能位于 .agents/skills，显式使用 $skill-name，触发依据实际宿主与描述。自然语言入口变更后用代表请求与反向请求复验，不因一次成功保证所有请求都正确
