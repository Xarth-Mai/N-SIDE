# 叙事试玩

## 何时测试

大纲用复述检查因果，文字原型检查信息与选择，灰盒检查动作与空间，整合构建检查完整体验。日常片段关注玩家如何参与、记住什么、在哪停留及是否愿意再来

每轮先确定体验意图、问题、路线和评分要点，再记录玩家原话、行为、研究者协助与实际状态

## 核心观察

| 结果 | 口径 | 调查型委托的初始参考 |
| --- | --- | --- |
| 目标清晰度 | 正确复述当前目标人数 / 回答人数 | 85% |
| 核心因果理解 | 正确复述约定因果链人数 / 回答人数 | 80% |
| 继续意愿 | 五分量表选择 4 或 5 的人数 / 回答人数 | 70% |

以上为待校准的项目参考值。报告同时记录人数与比例，例如 `8/10`；分母为零记录 `N/A`。小批次结果用于定位本轮问题，后续样板积累项目基线

每个结果关联构建、路线、测点与参与者经验，技术中断和退出另记。继续意愿采用 1–5 分，1 为非常不愿意、5 为非常愿意。核心因果评分要点在测试前写明

## 访谈与诊断

提问使用玩家自己的解释：“你现在准备做什么？”“这件事为什么发生？”“哪个细节改变了你的看法？”“你的操作造成了什么？”“这个角色想要什么？”

按本轮问题补充角色动机、线索理解、选择反馈、后果归因、揭示预期与停滞位置。会影响后续理解的问题放在结束后的回溯访谈中

## 修订与交付

因果错误对应大纲；线索顺序对应 Beats；观察不到变化对应场景和反馈；操作位置难找对应关卡；读档后状态差异对应实现

交付记录覆盖实际走过的路线、关键因果与信息、选择响应、跳过、重访和存读档。关键流程阻断项的交付目标为零，逐项记录处理与复测结果
