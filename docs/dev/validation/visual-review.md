# 视觉自查、隔离评审与真实试玩

机器断言与画面回答不同问题：有效 Transform 不证明入口清楚，截图完整不证明动作舒服。先按[运行验证](runtime.md)获得真实输入、状态和画面，再选择本页所需的观察方式；只改文档时使用文档检查，不补录无关游戏视频

## 输入与证据范围

输入为当前修改目标、构建及脚本版本、资源与场景、状态检查、实际图片序列或视频、复验前后差异。先确认目标行为确实发生且输出完整；断言失败的录像可以诊断，但必须保留 FAIL，不能选一张正常截图覆盖失败结论

| 方式 | 参与者与输入 | 能支持的结论 |
| --- | --- | --- |
| self-audit | 作者、实现者或读过设计/源码的 Codex；可以同时读规格与状态 | 指定画面中的构图、遮挡、材质、反馈和连续性问题 |
| 隔离评审 | 未见目标设计与源码的评审者；按事先协议只接收允许的真实画面与控制说明 | 该样本是否传达指定操作目标、选项与风险；不直接判定好玩或舒适 |
| 真实试玩 | 实际操作构建的作者或玩家，分别注明是否陌生、是否获提示 | 该设备、输入、路线和协助条件下的操作、理解与体验反馈 |

“新开一轮对话”不自动等于隔离；若已提供设计、答案、任务名称或实现上下文就按实际知情程度标记。代理评审不计作真实玩家，作者试玩不计作陌生玩家

## 视觉自查步骤

1. 在看结果前写清本轮要检查的内容与路线，例如进入转角时的遮挡或释放输入后的停稳；采样覆盖开始、变化、结束与必要恢复
2. 先检查 run/state 与日志，核对画面编号、时间、场景、分辨率和输入；缺帧、黑帧或错误资源先回到录制与加载诊断
3. 播放视频；无视频读取能力时解码并实际打开关键帧和跨动作的连续帧，记录看的帧号或时间段，不把生成 contact sheet 等同于已经查看
4. 分开记录观察与推断：入口、文字、角色轮廓、透明边缘、材料、高差、动作接触与效果时机；画面不能证明未执行的碰撞、任务或恢复路径
5. 每项问题指向具体元素、发生条件和证据，修复后保持相同条件复验；另记录仍未覆盖的平台、设备、距离和分辨率

默认 Viewer tour 为 640×360、18 秒自由相机操作，可检查已录制的位移、转向、释放与恢复及场景呈现；不能据此判定小字招牌、最终材质、人物碰撞、手柄、动画或委托体验已验收。需要更高分辨率或其他行为时修改本轮脚本并保留参数

## 隔离评审的使用条件

先冻结所问的操作目标、允许选项与风险判据，再选择录制和评审输入。采样方法在看结论前确定，不能为了好评只挑最清楚的截图；评审者不能参与驱动或接触答案，实际所见内容随记录保存

若使用上游 `gating-intent-legibility` 的完整门禁，必须执行其完整协议，包括真实取帧、回放状态比对、预先采样、按场景隔离、隐藏未来帧、顺序作答、事后预测核对及首次/协议变化时的降质对照。未满足这些条件，只报告实际完成的定性检查，不能沿用其 `legible`、`collapse` 等门禁结论或借用统计阈值

N:SIDE 的判断对象是必要操作、交互状态与危险是否可读；世界真相、人物隐情和异常谜底不要求提前读出。解释错误时区分界面缺失与设计上尚未获得的信息，先核对该时刻玩家可以知道什么

## 真实试玩与失败处理

具体组织见[试玩](playtesting.md)。记录构建、操作者经验、输入设备、路线、原话、提示和中断，实际反馈与机器日志分别保留。体验问题先判断目标、空间、动作、信息因果或恢复的来源，再决定改动，不用统一加箭头和对白处理所有不理解

没有可用隔离评审者时可以完成 self-audit；没有真实玩家或对应设备时保留 NOT RUN。评审证据不足可以记录发现与待测项，不能替作者批准体验或阶段出口

## 命令与输出

从仓库根执行以下 fish 命令，使用新输出目录保存本次录制；完整配置归 `game/capture/viewer-tour.json`，输出解释归[运行验证](runtime.md)

```fish
python3 tools/capture.py --script game/capture/viewer-tour.json --output output/capture/visual-review
ffprobe -v error -show_entries stream=codec_name,width,height,nb_frames:format=duration -of json output/capture/visual-review/video.mp4
```

没有 FFmpeg 时仍检查 PNG 序列，视频记为 NOT RUN；抽帧命令见[参考分析](../production/reference-analysis.md)。输出是一份任务内观察记录，至少包括机器 PASS/FAIL、实际查看范围、自查/隔离/试玩类型、具体发现、修复与复验、限制以及对下一动作的影响。机器 `visual_review` 默认未执行字段不会因截图成功自动变成通过，实际观察另行记录
