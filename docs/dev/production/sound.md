# 音乐、音效与配音

## 声音设计

声音覆盖生活空间、分时段街区、观景、梦境调查和战斗。每个声音记录情绪、叙事或玩法作用，以及触发情境

动作原型用临时声音验证预警、命中和交互反馈。Agent 的拟声、动作声与界面提示按其表达方式制作

## 交付

| 类型 | 记录内容 |
| --- | --- |
| 音效 | 事件、触发与停止、循环、变体、并发和空间位置 |
| 音乐 | 场景、情绪、结构、循环点与过渡；动态音乐另记分轨和同步点 |
| 配音 | 台词 ID、角色、语境、表演要求、录制批次、文本与音频对应 |

源工程放入 `source-assets/`，运行文件放入 `game/assets/`。音频交付记录采样率、声道、压缩、循环与响度；资产清单记录创作者与使用许可

对白使用稳定台词 ID，录制后修改的台词标记补录。主音量、音乐、音效和对白分别控制，字幕与视觉提示呈现关键信息

## 检查

检查触发、停止、循环、切换、暂停、存读档、音量和字幕对应

## 输入与制作顺序

专业方法使用 `audio-design`。输入包括所属场景或对象、真实触发动作、台词 ID、玩家需要听懂的反馈、同场景其他声音及既有素材来源。先读[资产管线](asset-pipeline.md)和对应系统规格，确认授权、唯一源与运行格式，再接入已锁定的 Bevy 能力；FMOD、Wwise、Seedling 和上游响度示例不自动成为项目依赖或定值

当前没有游戏声音事件实现，Viewer 显式禁用 `AudioPlugin`，其 capture 不含音频验收。以下事件表是首次接入的规格填写方法；实际源素材、总线实现、格式与混音数值由对应任务验证

1. 按业务事件区分输入接受、危险预警、动作接触、结果确认与持续环境，不让同一种提示承担相反含义；调查信息仍按已获得线索呈现
2. 为本轮事件填写 owner、start/stop、循环、空间、并发、优先级、音量分组和恢复；从少量临时素材验证事件准确性，不先生产完整音乐系统
3. 源工程保留分轨和可恢复编辑，导出记录格式、采样率、声道、循环点和增益；用真实听取与分析检查噪声、削波、循环接缝和字幕对应
4. 接入实际状态变化与 owner 生命周期，一次性声音播放结束释放实例，持续声音在状态退出时停止；重复触发、跳过对白与取消不得留下无主实例
5. 在实际场景听取音乐、环境、效果与对白的相互覆盖，先调分组和优先级；只有场景确实需要时才增加 ducking、分轨切换或节拍同步，保护必要预警和字幕
6. 复验正常、静音、连续触发、暂停、切场、重试及读档；机器记录触发次数与播放状态，真实监听记录设备、区间与听到的问题

## 声音事件样板

下面以“检查物件后关闭观察界面”为设计样板，便于规定循环清理，不表示游戏已具备该界面或已决定使用循环声。具体对象采用当前委托和资产清单的真实 ID，避免凭样板创建新对象

| 字段 | 填写示例与待确定项 |
| --- | --- |
| 事件与用途 | 观察进入/退出；仅在确有设备运行等声源时使用持续声，没有声源则不安排循环 |
| owner | 本次观察会话与场景实例；被观察对象的稳定 ID 用于追溯，不把旧实体句柄存入存档 |
| start | 观察状态成功进入、必需音频就绪后开始；同一会话重复进入请求不叠加 |
| stop | 正常关闭、取消、owner 销毁、切场与重试；重复停止无副作用 |
| loop 与空间 | 按素材定义循环点；来自世界设备则定位到设备，界面提示采用非空间声音，不能双重播放 |
| 并发与 priority | 该持续声每个 owner 至多一份；全局并发预算待真实混音与性能检查确定；必要对白与危险反馈优先 |
| bus / 音量分组 | 按其用途归音效或环境；主音量与组音量共同生效，具体实现待接入，不假定引擎已有混音总线 |
| 暂停 | 此样板的观察会话暂停时冻结该循环，恢复同一实例；实际页面若允许世界继续运行，在所属规格写明差异 |
| 存档与恢复 | 保存任务事实或有效场景状态，不保存临时播放实例；恢复后重新判断是否仍需该声源，不重播已提交结果 |
| 失败处理 | 可选环境声失败记录诊断并降级；必要声音失败保留可读视觉反馈并记验收失败，不能默默标为通过 |

## 生命周期与监听验收

| 操作 | 自动检查 | 实际监听 |
| --- | --- | --- |
| 一次触发与正常结束 | 事件只触发一次，实例正常释放 | 声音与动作时点一致，结束不截掉关键信息 |
| 连续触发或多个对象 | 并发按策略限制，owner 不串用 | 关键声不被重复提示淹没，无异常削波 |
| 暂停/恢复、跳过/取消 | 时钟和停止符合规格，无重复开始 | 无悬挂循环、突跳、意外重播 |
| 切场/重试/读档 | 旧场景实例归零，有效状态重建 | 新地点不残留旧环境声，完成提示不重复 |
| 音量/静音与对白 | 实际设置作用于正确分组，字幕仍可读 | 用实际耳机或扬声器检查清晰度；分别记录设备 |

从仓库根执行以下 fish 命令可检查工程并探测现有音频文件；`game/assets/` 暂无音频时第二条可能无匹配，不能以无匹配或构建成功代替音频运行

```fish
cargo test --manifest-path game/Cargo.toml --features viewer --locked
rg --files game/assets -g '*.ogg' -g '*.wav' -g '*.mp3' -g '*.flac'
```

接入后在任务中给出实际播放入口、路线及监听记录，按[运行验证](../validation/runtime.md)处理受影响场景。现有 capture 不录系统声音，视频不能证明声音通过；需要音频证据时使用可用录音能力或真实监听记录，缺少声卡、设备或听取能力记为 NOT RUN

## 输出与归属

交付源工程与导出、原资产清单更新、事件规格、代码入口、机器结果及实际监听。失败回到负责层：事件重复修状态，残留修 owner 生命周期，削波修混音，循环爆音修源素材与循环点；技术修复自主完成，体验与配音表演判断保留真实反馈
