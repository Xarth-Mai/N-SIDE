# 完整制作脚本的阅读与维护

完整制作脚本按任务保存在 `QST-xxx/script.md`，正文中的世界事实继续链接故事百科。脚本写明表演、镜头、玩家操作、条件内容与场景转换；同目录 `dialogue.csv` 是正式中文台词的唯一编辑源，脚本内带台词 ID 的文字是同批回填的阅读呈现。修改台词先修改 CSV，再同步呈现，不独立维护两份台词

## 场景与镜头

每场使用稳定的 `QST-xxx-Snnn`；已有场景 ID 保持原含义，新增场景在现有编号之后分配，阅读顺序由场次索引说明。每镜使用所属场景的 `QST-xxx-Snnn-Knn`，不把既有分场纲序号当作运行状态 ID

场景入口写出地点、时段、人物在场理由、初始站位与视线、持有和放置的道具、各自已经知道的事。镜头依次写相对场景地标的机位、景别、对象、运动和切换依据；动作写起手、过程、接触、停顿、对方反应与收势，接在实际台词之前、期间或之后。人物心意通过这些可见行为表达，表演注释不代替玩家应看见的证据

自由操作镜明确为玩家镜头，规定可见线索与响应，不把移动过程拍成强制过场。关键表演镜写出接管触发、临时屏蔽的输入、可跳过边界和交还控制的具体落点；暂停可用。跳过只落定已触发的演出，不替玩家取得尚未观察的证据、作出选项或完成未执行的操作

镜头长度以动作或对白完成为切换依据，可标建议节拍；不伪称灰盒尚未测得的米数、帧数或时长已经验证。恢复控制时保留实际位置或已演出的短距离就位，不把主角无说明地送到下一个地点

## 台词与屏幕文字

CSV 沿用 `line_id,speaker_id,text_zh_cn,context,recording_status,audio_path` 六列，ID 使用 `QST-xxx-Lnnn`。`speaker_id` 使用角色表中的 CHR 身份，旁白为 `NARRATOR`，纯界面和物件文字为 `SYSTEM`；无名人类说话者也登记真实独立身份，不能冒用 SYSTEM

`context` 按实际内容写明场景 ID、镜号、触发条件和表演关联。中文待录对白使用 `ready`，屏幕文字、物件文字及巧克力屏幕信息使用 `not_required`；尚无录音的 `audio_path` 为空。有明确作者的短信、便笺式通信和书面回复使用作者 CHR 身份并标 `not_required`，供演员阅读时仍能分清是谁在表达；公告、维修单、展签、资料摘录和无人格界面使用 SYSTEM。电话或录音中的真人声音按本人 CHR 标 `ready`。巧克力延续拟声、表情与屏幕表达，不新增人类长篇口语

剧本中的台词行统一为 `**QST-xxx-Lnnn｜显示名**：实际文本`，纯屏幕文字使用显示名“屏幕文字”。同一台词 ID 只在所属镜头展开一次；其他分支若共用，写明汇合镜头。角色称呼可用正文既有简称，CSV 始终保存其稳定身份

便签、消息、维修单、录音、校样、展签及公开说明写成实际可读原文。同一条屏幕长文中的 `\n` 标注排版换行，不作为物件上的字样；分行唱词各有自己的台词 ID。屏幕提示只告诉玩家现场能理解的事，不把任务 ID、条件变量或制作备注显示给角色

## 分支与出口

既有选项写出玩家所见文字、选择条件、实际回应、动作和后果，再指出明确的汇合场景或镜头。提前发现、先后顺序、未做相关支线、拒绝、延后及重访分别处理发生变化的部分，其余引用公共后续，不复制整场

每场出口说明人物怎样离场或继续等待、道具位置、已完成与未完成的事、下一目标，以及中断后从何处续接。每篇以具体重访对白和动作结束，不用“按进度回应”替代正文。自然日推进使用明确转场，不把现实等待计作任务长度

现有任务没有改变结果的分支时保持线性，不为了格式增加假选项。已选择的退款、转修、作品版本、公开范围与寄物／资料路径直接继承；没有执行的支线不能被写成角色的回忆
