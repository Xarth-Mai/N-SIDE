# Null Site空间设计决策

关联任务：[Null Site扩容与轻近未来都市设计](../../../todo/archive/legacy/n-district-modern-city.md)，原地图记录见 [TASK-001](../../../todo/archive/legacy/n-district-space.md)

## 城市组织参照

按作者要求，长崎作为地形与城市组织的整体现实参照，依据与适用边界见[城市空间研究 R15](../design/locations/world-research.md#r15-长崎的山地城市结构)。低地交通与商业中心、山腹住宅、沿坡生活道路、公共升降设施、人工台地及滨水日常共同落实，具体制作职责见[街区空间制作](../design/locations/district-space.md#整体城市参照与空间落实)

当前沿用白沙河两岸都市与 Null Site 双中心。长崎的海港地形是否引入河口港湾尚待作者选择，既有河流、渡口与剧情水位关系继续有效。城市人口、历史事件、地方文化与名称沿用 N:SIDE 设定，现实资料的高度与坡度仅支持空间推演，具体项目参数由地形、道路和镜头共同验证

## 街区布局

以原 29 个图面点位、六组生活空间和核心邻接关系为扩容种子，按双中心、10—14 个街坊、220—350 个本岸建筑体量及 70—100 处特色场所深化。首轮以 12 街坊、280 个建筑体量、84 处场所起排，24 处重点深化；数量随地块与容量校核调整。地图采用固定正交斜俯视导览，表达相对位置、地势与建筑体积；具体尺度在后续空间制作中校核

站前回家路紧凑而有层次，经过站前、商店街、弯口与树下空间。城区由低街、坡路与错落台地上升，建筑在台地上保持自身尺度；中段从建筑间隙看见河面，到观河转角再展开视野。当前路线距离与高差从[总图](../design/locations/district-plan.md#距离与坡度)读取

摘星台位于北坡最高点，山体以这一座主峰组织轮廓，侧脊与山肩低于峰顶。小店位于山坡起点，店后住宅台地直接沿山势层层抬起；登高路线沿坡折返经过休息处和神龛，下山设另一条公共路径，接坡上住宅和公共台阶，住宅段另有缓路可选

设计范围覆盖本岸街区，对岸作为背景。桥梁与渡口保留城市联系，当前可达范围止于桥头和渡口入口

## 山城高程与登高目标

统一以白沙河水面为相对高程 0，平面与竖向均使用设计米。当前设计目标如下，不另加绝对海拔偏移，也不通过 Viewer 纵向缩放改变比例

| 部位 | 设计目标 | 空间关系 |
| --- | --- | --- |
| 小店与山坡起点 | +28 m | 河岸起算的地标折线剖面约374m处，店前平台保持平整，店后开始明显起坡 |
| 坡地住宅与林缘入口 | 按道路、宅地与局部设施逐级抬升 | 住宅沿山腹台地分层，生活路沿坡横向展开，台阶串联上下街 |
| 摘星台山顶 | +450 m | 北坡唯一最高点，面向城区的山体轮廓与可到达的观景终点重合 |

小店附近开始进入山坡街坊，以原剖面约374m／+28m至约1km／+450m作为比例参考，具体距离服从街坊与山体的整体关系；这些距离从河岸起算，表示各地标间平面直线的累计距离，不是道路里程或小店至峰顶直线距离。小店至山顶净登高422m，坡地街坊嵌入山腹。近店允许较缓的人工台地和过渡，之后逐层接续更陡山势；住宅台地、挡墙、沿坡生活路和公共台阶共同构成山城，不要求保持未经改造的自然坡面，也不为了参考数值把生活街坊抬成巨墙。固有场所名“山脚休息台”继续沿用，其位置承担坡上林缘步道入口，不再作为自然山体开始起坡的位置

山径以折返、休息平台和较陡短段的实际台阶分配爬升，当前实算长度见[总图](../design/locations/district-plan.md#距离与坡度)。门前、院落与建筑基底保持局部平整，生活道路沿山势横向绕行，近路通过公共台阶连接；山面的自然坡度不等于道路纵坡，配送与无台阶路线分别核对，不能把全部路段强行拉成同一陡坡。站前、采购、小店和镜厅保留地面缓行替代路线；更高的住宅街可使用真实公共电梯及平台接入，后勤转运使用独立服务设施，不把它们伪装成连续车行坡道

城区抬高采用分区台地与接续道路。建筑只调整落地高程，层高、总高、门洞和楼梯尺度保持原有设计；同栋多层入口与外部街道一起核对。镜厅低街至公共屋顶保持 12 m 局部高差，屋顶、建筑外平台和公共电梯仍分别归属

从站前、镜厅前街与小店门前的人眼高度检查坡上住宅和山顶的相对关系：近处街面保持可用的平整空间，中景台地连续上升，最高点从街道或建筑间隙抬出；侧脊提供不对称轮廓，不形成另一座与摘星台争夺视觉中心的峰顶。这些值是当前空间设计基线，地图必须与之对齐；路段长度、坡度、道路与入口接缝、视线及运行画面由实际数据和场景检查验证。静态总图、道路连通或固定镜头不单独证明玩家可通行、NPC 可导航或实机体验已验收

## 月台杂货与住家

兄妹和顾客日常共用店门，回家经过营业空间，再从后场门进入私人内楼梯。收货另设受控服务门，连接侧院与储物区。公共店侧台阶保持建筑外的街区通路

楼上以餐厨与起居为共同生活中心，共同创作区相邻，各自私人休息空间保持独立

日常设计需求与异常委托共用可关闭的预约洽谈位，按时段安排。后场设备工作间兼作潜梦室，启用前收起维修物件，身体安置和接应位置保持清楚，维修与潜梦错时进行

夜间整理以后场为主，通过门口或内窗与 Agent 接待区保持联系。小店全天营业，补货、整理与顾客通行分开

## 地图预览

Wiki 共用一份 JSON 渲染“街区风貌”与“道路结构”。默认显示风貌，建筑具有屋顶、墙面与落地阴影，地形用连续坡面和统一受光表现，明显侧面用于真实平台、河堤与挡墙

道路结构淡化建筑，保留道路、地块边界与低浅高深的高度配色。全图与小店附近提供快捷取景，支持放大、全屏及地点详情；全图主要展示街坊与少量地标，具体地点在局部显示，密集处用索引补充

先以小店、树下空地、邻接店屋、公共台阶、上层住宅与背侧服务巷核对画法，再将同一绘制规则用于全街区。隐藏名称后仍应能辨认门前平台、上坡通路、收货位置与私人边界

地点、道路与两岸关系沿用同一组空间坐标，取景不压缩世界里的上山距离。建筑落地高程与建筑高度分别维护，高程和体量均为设计假设，视觉体积不代表通行或工程验收

## 后续边界

具体室内层数、面积与装饰随小店深化确定，本轮先记录功能邻接。空间尺度保留为设计目标，简图坐标不代替实际比例与高程校核

N站轨道形制、渡口结构、水位适应方式与极端天气关闭范围仍需专项确定。摘星台保留两面夜景，异常成因待定。后续人物与日常片段依托扩容后的具体场所，场所、建筑与内部经营单元分别统计
