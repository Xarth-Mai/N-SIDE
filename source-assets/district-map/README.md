# Null Site地图数据

[district.json](district.json) 是 Wiki 斜俯视导览图的唯一主数据，地点索引由同一份数据生成

| 字段 | 值 |
| --- | --- |
| 资产 ID | `AST-002` |
| 状态 | `working` |
| 来源 | 地点索引参考 `n-side-district-map.html` 概念地图，布局依据街区空间设计重绘 |
| 原始参考作者与许可 | 待确认 |
| 用途 | 街区位置关系、地势与地点总览 |

`blocks` 保存街坊范围与容量，`parcels` 保存用地边界、入口及建筑容量；场所通过 `parcel`、`building` 与 `parent` 关联空间，共楼对象按用途独立计数。`featured` 区分目的地与辅助节点，24 处 `brief` 保存空间简报，Wiki 直接生成场所卡

`nodes` 保存道路平面位置与高程，`roads` 引用节点并记录道路类型。`buildings` 分别记录落地高程 `elevation`、建筑高度 `height`、轮廓和建筑类型，`surfaces` 保存平台、院落及公共边界。`places` 维护地点编号、名称、用途和入口说明

山城的高程与登高目标见[空间设计基线](../../docs/dev/decisions/district-baseline.md#山城高程与登高目标)。所有高度采用水面为 0 的相对高程，摘星台所在主峰与两侧较低的山脊由地形控制点表达，摘星台节点与地形最高点重合；场景使用统一米制比例。山坡起点从小店开始，剖面距离从河岸起算；坡上林缘入口与小店起坡段分别表达。调整城区台地时同步道路、地块、建筑基底、平台和入口，保持建筑自身层高、总高与门洞尺度；镜厅低街至屋顶的局部高差保持 12 m

场所的 `access` 是街坊接入点，`arrivals.public` 与 `arrivals.service` 保存从接入点到门口的完整节点路径、入口名称和楼层；标高直接读取末节点。道路 `access: service` 表示后勤专用，`controlled` 表示受管理的到访路径，`width` 记录每段道路的实际设计宽度。楼内通路关联 `building`，屋面与外部平台通路关联 `surface`

屋面表面用 `building` 归属建筑，屋面外平台独立保存轮廓与高程。规划容量、已落图和剩余容量按地块生成，保留建筑计入容量，街坊和全区统计沿用同一口径

`terrain` 保存水面边界与坡地高程控制点。Wiki 与 Viewer 采用相同的地面道路筛选、Delaunay 三角网和重心插值，桥面、屋顶、室内与高架节点独立于自然地面；控制点直接成为地形顶点，场景外延 120 m 沿用最近控制点高程。固定正交镜头从河侧斜看坡地，俯角为 55°；地形面按坡向受光，墙面、屋顶、树冠和桥梁按前后关系绘制。平台先于立体物件绘制，避免院地覆盖房屋

街区风貌与道路结构共用数据，后者淡化建筑并以低浅高深的颜色辅助表达高差。全图、小店附近、缩放及地点索引只改变取景，不改变地点坐标或道路尺度。名称朝向屏幕，密集地点在放大后显示，也可从索引选择

`sections` 与 `routes` 引用同一份道路节点，剖面累计平距并单列垂直交通；`connections` 表达图外城市关系。住房量级同时按地块参数和已落图建筑楼面与 `housingAssumptions` 复算。总图、剖面、场所卡和风貌图均从本文件派生

`architectures` 按稳定样段 ID 保存边界、建筑引用、立面视向、剖切线与生活场景。建筑 `design` 记录类型、方案状态、主要用途层与外部入口，坐标均沿用设计米；楼层标高为相对高程。`framework` 状态记录城市框架深度，室内参考只保留在已有样段。`entries` 通过节点、使用者与楼层记录门口，入口与道路共用高程；公共屋顶层位于建筑顶标高。`baseline` 只保存指定提交的建筑轮廓，用于同范围体量对照；现行设计仍只修改 `buildings`。各样段通过 ID 选取同一绘图组件，Wiki 页面承载小店坡地段与站前兴趣段；影院滨水段与全区框架直接复用城市总平面和外部剖面

`logistics` 按车辆与推车分别引用城市接入、装卸和货门路径。道路 `access: resident` 供住户使用，`controlled` 的 `users` 列出授权使用者；生活路线及受管理到访通过 `user` 指定角色，普通公众默认使用开放道路

平面以设计米坐标校准，高程、建筑高度与地形控制点均为设计假设，不作为测绘或工程尺寸。地块容量与已绘制体量分别统计，屋顶和电梯上层节点排除出地面插值。地点编号与正式地点 ID 独立，生活设定与制作要求维护于 Wiki

修改后运行 `bun run check:map` 和 `bun run docs:build`，检查小店无标签画面、桥下衔接、两种视图及移动端取景。发布使用显式资产清单，不另存独立修改的地图副本

## 自然山面细化

`terrain.samples` 同时保存手工控制点和离线细化结果；`terrain.bake.authored` 指定手工前缀长度，其后的样点由 `bun tools/terrain-shape.ts` 重建。新增手工点放入前缀并同步计数，避免写进会被覆盖的生成后缀；`version`、`seed` 与 `spacing` 记录生成规则版本、固定种子和采样间距

先确定城区台地、摘星台最高点、道路与入口，再调整自然山形；生成器以多频起伏和方向性山脊细化自然区域，以道路和场地的距离约束减弱扰动，并锁定自然山面覆盖范围内地面平台与建筑的边界控制点，避免粗采样跨过边缘形成孤立护坡。结果烘焙回同一地图，Wiki 与 Viewer 均读取这些样点，运行时不再随机生成另一座山

修改手工点、路线或参数后运行 `bun tools/terrain-shape.ts`、`bun tools/terrain-shape.ts --check` 和 `bun run check:map`，再按[运行验证](../../docs/dev/validation/runtime.md)检查街道视线、山脊、道路接缝与平台落地；参数正确不能代替实际看图。长折返路应沿连续山面布局，避免把相邻路径的巨大高差强压进很短的水平间距
